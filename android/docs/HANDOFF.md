## Toolchain (user-scoped, already installed)

- JDK 21: `%LOCALAPPDATA%\DevTools\jdk21`. Android SDK: `%LOCALAPPDATA%\Android\Sdk`. adb: `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`.
- Build (PowerShell, from `android\`):
  `$env:JAVA_HOME="$env:LOCALAPPDATA\DevTools\jdk21"; $env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"; .\gradlew.bat test assembleDebug lintDebug --console=plain --continue *> build.log`
  Check `$LASTEXITCODE` and grep the log for ` FAILED$`; with `-q` piped through `Select-String` a failure can be missed.
- Debug APK: `android\app\build\outputs\apk\debug\app-debug.apk` (a normal debug rebuild overwrites the separate test APK). Signed, optimized release APK: `android\app\build\outputs\apk\release\app-release.apk`. Release `0.1.7` / code `8` has minSdk 25 (targetSdk 36), a verified v2 signature and alignment, and is installed on three Fire Sticks (API 25, 28 and 30). The release folder currently holds a renamed copy, `8player.apk`, rather than `app-release.apk`. The user reports (2026-11-14) the released app working on Fire OS 6 and 7; the full release smoke matrix (Fire OS 8, phones, readability, every playback path) is still to do. The API 28 and 30 Sticks were updated in place. The older API 25 Stick's differently signed regular app was removed with user approval before installation, deleting that app's data; its separate test app remains installed with its own data. Rebuild and verify signing before relying on an APK after further changes.
- Release branding: app label **8TV Player**, Midnight Wordmark app-icon concept 2, and a matching 320×180 TV launcher banner. Concepts are in `android/docs/mockups/8tv-app-icon-concepts.html`. Adaptive icon foreground: `app/src/main/res/drawable/ic_launcher_foreground.xml`.
- Signing: a new release key is in the Windows user's `%USERPROFILE%\8TV-Player-Signing` outside the repository; the password is protected using the creating Windows account's DPAPI. Back up the keystore and a separately recoverable password securely; the DPAPI file alone is not a portable backup. See `android/docs/distribution.md` for release builds and recovery guidance. Debug and release share an application ID but have different signatures: uninstalling debug before installing release removes its app data. A Drive API key restricted to a signing fingerprint must include the release certificate if used.
- `android/local.properties` (git-ignored) holds `sdk.dir` and `tmdb.apiKey`. No Drive API key is set, so Drive downloads use the public fallback URL.

  - Skip intro / recap / credits: `VodPlayerOverlayState` offers a skip prompt (OK on TV, button on phone). Real spans come from TheIntroDB (`:core:network` `skip/IntroDbClient`, `GET https://api.theintrodb.org/v2/media?tmdb_id=&season=&episode=`, no key). `SkipSpanRepository` looks them up by TMDB id, has a 4 s timeout and a bounded in-memory cache (empty results cached, failures not cached), and never blocks playback. If no spans exist, position-based intro and credits guesses are used; when spans exist without credits, a credits guess can still appear. Guesses can be inaccurate; recap has no guessed fallback. Only TMDB id, season and episode are sent, never provider data.
  - Skip data research: TVDB v4 has no skip data. IntroDB (`introdb.app`, IMDb id, intro/recap/outro) and AniSkip (anime, MAL id) work without a key but are not wired. IntroDB would be the next fallback; it needs an IMDb id from TMDB. Terms and rate limits of these services are unchecked (TheIntroDB sends rate-limit headers).

Dropped frames reset when the decoder is recreated. A high buffered duration during stutter argues against assuming network starvation.
- The user observed a 160 MiB player buffer against a 192 MiB app heap on 0.1.2. On 0.1.3, the user reported the same 4K episode played smoothly without a crash, with about 49 MiB in the player buffer and 94 MiB used heap. Further sustained 4K, rebuffer recovery, seek-back and guide stress testing remain; the allocator target is a loading threshold, not an absolute allocation ceiling.

- Search's first query of a session can wait behind a running heavy background job.

## Rules

- Never print, log or commit hostnames, usernames, passwords, Drive file IDs or API keys. Personalized `8k_*.m3u` files contain credentials. Tests use `example.invalid`.
- Don't stage local data (`data/config/*` tokens and backups, generated playlists).
- Follow the active repository and session commit conventions when committing.
- The user's token budget is limited: keep agents few and reports short.
